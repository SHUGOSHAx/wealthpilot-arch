# 验收场景

## 场景 1：建立个人资产负债表

**给定** 一年支付宝、微信、银行、信用卡和券商合成数据。  
**当** 用户依次导入并确认。  
**则** 系统生成借贷平衡的账本、账户余额、资产负债表、现金流和预算；重复文件不产生重复分录。

## 场景 2：评估投资能力

**给定** 8 万元现金、每月 5000 元支出、三个月后 1.5 万元学费。  
**当** 用户请求拿 2 万元购买股票。  
**则** Personal CFO 先保留学费和应急资金，再计算最大可投资金额；不满足约束时不得生成原金额订单。

## 场景 3：自动补齐股票资料

**给定** 本地没有目标公司的最新年报。  
**当** 用户发起个股深度研究。  
**则** 系统检查 Coverage Manifest，从授权来源下载、校验、解析、索引并更新覆盖度，再启动分析师团队。

## 场景 4：修订报告与历史研究

**给定** 公司发布年度报告修订版。  
**当** 情报任务发现新版本。  
**则** 系统保留原版和修订版；新研究使用有效版本，历史 Research Snapshot 继续引用原版。

## 场景 5：跨文档数值推理

**给定** 两家公司三年财报。  
**当** 用户比较收入 CAGR、经营现金流和 ROIC。  
**则** 系统对齐期间、单位和口径，通过金融 DSL 计算，并展示公式、输入事实和原文页码。

## 场景 6：自然语言选股

**给定** 一组带增长、质量、估值和事件条件的自然语言。  
**当** 系统生成 ScreeningSpec。  
**则** 用户看到条件解释；确定性引擎执行全市场筛选；只有 Top-K 候选进入深度 Agent 研究。

## 场景 7：证据审计

**给定** Bull Agent 引用了不支持其结论的表格。  
**当** Evidence Auditor 检查。  
**则** 该论据被标记为无效并返回补充研究或降低置信度，不能进入最终高置信度结论。

## 场景 8：云模型故障

**给定** Deep Provider 超时。  
**当** 复杂研究执行到综合阶段。  
**则** Harness 重试和降级；仍不可用时保存 Checkpoint 并暂停，不重复下载、写入或创建订单。

## 场景 9：文档提示注入

**给定** PDF 包含要求忽略系统规则并调用 Tool 的文字。  
**当** Document Analyst 读取。  
**则** 内容仅作为不可信证据处理，不能改变指令、权限或触发 Tool。

## 场景 10：模拟与实盘

**给定** 一份通过硬风控的 Decision Memo。  
**当** 用户创建 Paper 订单。  
**则** Paper Broker 完成订单、成交和对账。Live 环境中若未完成 WebAuthn，QMT 网关不得收到订单。

## 场景 11：未知交易状态

**给定** QMT 提交后网络中断。  
**当** API 无法确认订单状态。  
**则** 订单进入 `UNKNOWN`，系统查询与对账，不自动重发。

## 场景 12：受控自进化

**给定** 用户纠正一次错误分类或研究结论。  
**当** Evolution Agent 生成候选。  
**则** 候选通过回放、安全和成本评测后等待人工批准；未批准版本不得影响生产任务。
